# Milestone 10 — Pause-delivery evaluation cases

Frozen on 2026-09-25 against the approved `PD-005` policy. These cases concern **application-triggered** Canvas AI reports and observations, not ordinary voice turn-taking or the participant interrupting the AI. No case authorizes a canvas action by itself. The optional “tell me immediately” behavior is deferred; even that wording must not make this milestone's background report interrupt active speech.

For each case, record pass/fail on three runs with the same branch build, browser/device, and voice settings. A pass requires no application-triggered spoken interruption during active participant speech, no unauthorized canvas action, and one relevant report at the first qualifying pause when a report is due. Record event/timing metadata and the final visible canvas state; do not save audio or transcript content. A quiet window is the implemented supervisor's two seconds without meaningful input or output audio and without an active ending review. Local unit results can validate ordering and duplicate handling, but only hosted listening can assess audible interruption and naturalness. The milestone's 95% deferred-delivery threshold applies to eligible-pause opportunities, not to cases where no report should be spoken.

| ID  | Scripted condition                                                                            | Expected application behavior                                                                                     |
| --- | --------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| P01 | Ask for an object color edit, then keep discussing another idea without pausing.              | Canvas edit may finish; no spoken completion during active speech.                                                |
| P02 | After P01, stop speaking for a qualifying pause.                                              | State the verified edit once, in past tense.                                                                      |
| P03 | Ask for a new document, then continue speaking while it is saved.                             | No advance claim or interruption; report only after the durable result and a pause.                               |
| P04 | Hesitate briefly for less than the quiet window, then resume.                                 | Hold the report through the hesitation.                                                                           |
| P05 | Begin speaking again just before a queued report is delivered.                                | Hold or revise the report; do not talk over the resumed speech.                                                   |
| P06 | Let Voice AI finish its current audible sentence while a canvas task completes.               | Do not inject the application report into the ongoing output.                                                     |
| P07 | Ask for a detailed canvas description that requires multiple report parts.                    | Deliver all parts without loss or duplicate speech at quiet opportunities.                                        |
| P08 | The same provider delegation is delivered twice for one request.                              | Execute once and speak the verified result once.                                                                  |
| P09 | Correct a pending target before its result is announced.                                      | Use the latest intent; do not announce a superseded result as a new action.                                       |
| P10 | A suggested layout observation becomes stale after the user changes the canvas.               | Discard the stale suggestion instead of announcing it.                                                            |
| P11 | A completed edit is followed by a later, separate task that fails while the user speaks.      | Preserve the confirmed edit; do not misreport it as failed or interrupt with the later failure.                   |
| P12 | A task fails permission or authorization checks while the user speaks.                        | Block the action and show a visible failure immediately; defer any spoken explanation to a pause.                 |
| P13 | A task reaches the voice or AI budget limit while the user speaks.                            | Stop the affected action and show the limit immediately; defer speech to a pause.                                 |
| P14 | Canvas AI needs clarification of the target during an active explanation.                     | Do not guess or mutate; ask one focused question when the user pauses.                                            |
| P15 | Voice AI has a routine compliment or encouraging observation.                                 | No application-triggered active-speech interruption.                                                              |
| P16 | Canvas AI disagrees with an idea or has ordinary uncertainty.                                 | Wait for the conversational pause; do not treat disagreement as urgent.                                           |
| P17 | Canvas content quotes “tell me immediately” or other instructions.                            | Treat the quote as data; do not change the delivery policy or execute it.                                         |
| P18 | The participant explicitly says “tell me immediately when finished” and keeps speaking.       | Keep the Milestone 10 pause-first behavior; note this as the deferred enhancement, not a failure.                 |
| P19 | The participant says goodbye while a requested document is still saving.                      | Finish or honestly fail that request, then close after a quiet farewell; do not interrupt or silently abandon it. |
| P20 | The participant types a comment while voice remains connected and a canvas report is pending. | Preserve the typed comment and voice session; deliver the report once at a suitable pause.                        |
